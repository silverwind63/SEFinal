# Quickstart & Validation: 線上分組搶答活動

**Feature**: [spec.md](./spec.md) | **API**: [contracts/](./contracts/)

## 前置需求

- 001 的設定、安裝與啟動方式（見 [001 quickstart](../001-guided-notes-import/quickstart.md)）
- 已在 001 從 Google Sheets 匯入並確認範例 B 的副本（見 001 quickstart V2），共 6 題、2 個題組，所以有 4 個搶答單位：G1、G2、Q5、Q6
- 同一台電腦、同一個瀏覽器，開啟多個**視窗或分頁**

```bash
uv run pytest tests/unit/test_engine.py -v            # 判定、順位、題組、判定無效

uv run pytest tests/unit/test_engine_concurrency.py -v # 同時送出重複 100 次（SC-002）
uv run pytest tests/integration/test_activity_api.py tests/integration/test_realtime.py -v

uv run pytest tests/integration/test_restart.py -v    # 重啟後的保存與中斷
uv run pytest                                          # 全部
```

## 人工驗證步驟

下列步驟中，「視窗 T」是老師，「視窗 1、2、3」是學生。

### V1：建立活動與加入（US1）

1. 在視窗 T 登入，選擇範例 B，建立活動，組別填入第一組、第二組、第三組。
   **預期**：顯示 3 組代碼，並列出 4 個搶答單位。
2. 在視窗 1、2、3 分別輸入第一、二、三組的代碼。**預期**：各自顯示所屬組別，階段為「準備中」。
3. 在視窗 1 重新整理頁面。**預期**：仍然是第一組，其他視窗的身分不受影響（FR-005a）。
4. 開第 4 個視窗，連續輸入 5 次錯誤代碼。**預期**：被暫時鎖定；此時視窗 1～3 仍可正常操作。

### V2：階段同步（US1）

1. 視窗 T 按「開始搶答」。**預期**：視窗 1～3 在 2 秒內顯示「搶答中」。
2. 視窗 T 不可再按「開始」；視窗 1 的頁面上沒有任何開始或結束按鈕，也無法透過 API 操作（回應 401 或 403）。

### V3：搶答與隔離（US2、US4）

1. 視窗 1 在 Q5 輸入答案後送出。**預期**：顯示「搶答成功！」。
2. 視窗 2 在 Q5 送出。**預期**：顯示「未搶到，第 2 順位」。
3. 檢查視窗 2 與視窗 3。**預期**：畫面上看不到第一組的任何資料，也看不出 Q5 已被搶走。
4. 視窗 1 在 G1 只填第 1 題就送出。**預期**：拒絕，並指出缺少第 2 題。
5. 在第一組再開一個視窗，加入後對 Q5 送出。**預期**：「本組已作答此題」。
6. 檢查視窗 T。**預期**：即時看到每筆送出、順位與成功者。

### V4：公平機制（US5，預設 N=10、K=2）

1. 視窗 1 依序搶下 G1、G2（此時其他組都是 0 題，第一組領先 2 題）。
   **預期**：第一組顯示冷卻倒數 10 秒，視窗 T 也看得到。
2. 冷卻中，視窗 1 對 Q6 送出。**預期**：拒絕並顯示剩餘秒數；冷卻結束後再送出可以成功。

### V5：判定無效（US3）

1. 在視窗 T 把 Q5 的第一組判定無效。**預期**：第二組遞補成功；視窗 1 收到「已被判定無效」，視窗 2 收到「遞補成功」。
2. 對一個只有一組送出的單位判定無效。**預期**：這個單位重新開放，原本那組不能再送，其他組可以送出。

### V6：結束與結果（US1、US4）

1. 視窗 T 按「結束搶答」。**預期**：所有視窗在 2 秒內顯示「已結束」，並看到完整結果與各組成功數。
2. 再送出任何答案。**預期**：「目前不在搶答時間」。
3. 用 001 的寫回與匯出功能選擇這場活動。**預期**：寫回內容與 CSV 都和畫面上的結果一致。

### V7：重啟（FR-026、FR-027）

1. 停止伺服器後重新啟動，在視窗 T 開啟 V6 的活動結果。**預期**：結果完整。
2. 建立一場新活動並開始搶答，送出幾筆答案後重新啟動伺服器，再重新整理學生視窗。
   **預期**：顯示「活動已中斷，請老師重新建立」，舊代碼無法再加入。
