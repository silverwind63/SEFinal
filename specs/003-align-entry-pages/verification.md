## 真實環境完整驗證（2026-11-28）

PR #8 合併後，在使用者的電腦上用真實的 Google Sheets 從頭操作一次。

- **環境**：
  - 伺服器：macOS、`uv run python -m guided_buzz`（`127.0.0.1:8000`）。
  - 瀏覽器：Safari，開了 1 個老師視窗與最多 4 個學生視窗。
  - Google：以 OAuth 登入（11/27 授權）。
- **學習單**：「範例B_搶答驗證」副本。開始前已確認 6 個填空格都是空白。
- **核對方式**：
  - 操作由組員在瀏覽器進行。
  - AI 讀取伺服器 log 與資料庫，並以同一個 OAuth 授權讀取試算表來核對（只讀取，不寫入）。
  - 畫面上的訊息由組員回報。

|---------|------|-------------|
| E-01、E-03、E-04 | ✅ | 首頁是「加入組別」，有「我是老師」，沒有密碼欄。按「我是老師」後進入 `/teacher`；登入後 5 個區塊依序排列，頁首只有「登出」（組員確認） |
| E-05 | ✅ | 在 `/teacher` 匯入並確認學習單後，直接在同一頁建立活動 |

| E-08 | ✅ | 學生視窗重新整理 6 次，都直接回到作答畫面。<br>老師視窗重新整理後，以 `/api/auth/session` 確認身分，維持登入，並回到最後檢視的活動 |
| E-09 | ✅ | 重新產生代碼後，學生視窗回到「加入組別」，並顯示「老師已重新產生本組代碼…」；用新代碼可以再加入。<br>伺服器重啟後，學生視窗自動回到「加入組別」，並顯示「活動已中斷，請老師重新建立。」（組員確認） |
| E-10 | ✅ | `/student.html`、`/teacher.html` 都回 307，並導向 `/`、`/teacher` |
| 其他 | ✅ | 已有進行中的活動時再建立活動，回 409（ACTIVITY_IN_PROGRESS）。<br>伺服器重啟後，老師需要重新登入；「目前活動」顯示沒有活動；檢視已中斷的活動時顯示錯誤訊息（組員確認） |

**操作上的觀察**：老師頁重新整理後，「目前活動」會回到最後檢視的那一場（第三場）。組員以為那是第一場，就按了「寫回答案」，結果寫回的是第三場。因為第三場沒有任何送出，所以試算表沒有被改動。這不是程式錯誤，但「目前活動」只顯示階段與活動編號，在有多場活動時不容易分辨。
已處理：「目前活動」補上學習單名稱與建立時間；活動清單中目前那一列加上底色，按鈕改為「目前檢視中」。

## 驗證中的發現與處理

1. **訊息區在長頁面上看不到**：老師頁合併後變得很長，訊息區又在頁尾，捲到上面操作時看不到結果與錯誤。學生頁冷卻時被拒的訊息也有同樣問題（002 驗證時曾連按 28 次）。已把訊息區改成固定在畫面底部（`style.css`，T017）。
2. **類別圖與實作不一致**：圖中把舊網址導向畫成前端元件，實際是後端 `api.page_routes` 處理。已更新類別圖（T021）。
