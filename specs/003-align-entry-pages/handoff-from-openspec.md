# 交接：入口頁與老師頁面對齊 OpenSpec 組（給 SpecKit 組）

> 本檔為 OpenSpec 組交接文件的原文，作為 [spec.md](./spec.md) 的需求來源，保留不修改。

寫給 SpecKit 組（`silverwind63/SEFinal`），由 OpenSpec 組整理，2026-11-27。

## 為什麼要改

兩組對照操作時，發現進入系統的方式不同：

| | OpenSpec 組 | SpecKit 組（目前） |
|---|---|---|
| 首頁 `http://127.0.0.1:8000/` | 學生的「加入組別」，旁邊有「我是老師」按鈕 | 只有老師密碼登入 |
| 學生怎麼進入 | 在首頁輸入組別代碼，網址不變 | 要自己把網址改成 `/student.html` |
| 老師怎麼進入 | 在首頁按「我是老師」，進到 `/teacher` 登入 | 在首頁直接登入 |
| 老師的功能 | 全部在 `/teacher` 這一頁 | 分成兩頁：「學習單與結果」（`/`）和「搶答主控台」（`/teacher.html`） |

兩組討論後決定：**SpecKit 組完全對齊 OpenSpec 組的做法，OpenSpec 組不改。** 這次只改前端頁面與兩個頁面路由，後端 API、判定、權限和資料都不用動。

## 目標

| 網址 | 內容 |
|---|---|
| `http://127.0.0.1:8000/` | 學生頁：「加入組別」表單，加上「我是老師」按鈕。學生加入後，作答畫面也在這一頁，網址不變 |
| `http://127.0.0.1:8000/teacher` | 老師頁：未登入時顯示「老師登入」；登入後，**老師的所有功能都在這一頁**，網址不變 |
| `/student.html`、`/teacher.html` | 導回對應的新網址（見第 3 節） |

## 要改的內容

### 1. 首頁 `/`：學生頁

目前 `student.html` 的內容改放到首頁，取代現在的老師登入頁。

- **未加入時**顯示「加入組別」區塊：
  - 標題：加入組別
  - 說明：每個瀏覽器視窗各自保有自己的身分，可以在不同視窗分別開啟老師與各組畫面。
  - 欄位：組別代碼（老師發給各組的 6 碼）
  - 兩個按鈕並排：「加入」（送出表單）和「**我是老師**」（連結到 `/teacher`）
- **按「加入」**：照舊呼叫 `POST /api/join` 並帶 `X-Window-Id`。成功後，在同一頁顯示原本 `student.html` 的畫面：組名、目前階段、冷卻、作答、結束後的結果與各組成功數。網址維持 `/`。
- **加入後**，「加入組別」區塊和「我是老師」按鈕都隱藏。
- **身分失效時**回到「加入組別」區塊，並顯示原本的提示訊息。例如組別代碼被老師重新產生，或活動已中斷時的「活動已中斷，請老師重新建立。」
- **重新整理頁面時**，sessionStorage 裡有學生 Token，就用 `GET /api/me` 檢查。有效就直接顯示作答畫面，無效就回到「加入組別」。

### 2. `/teacher`：老師頁（把兩頁合成一頁）

**路由：** 新增 `GET /teacher`，回傳老師頁的 HTML，網址沒有 `.html`。
- `StaticFiles(html=True)` 不會自動把 `/teacher` 對應到 `teacher.html`，所以要在 `api/app.py` 另外寫一個路由，例如回傳 `FileResponse`。
- 這個路由要放在最後的 `app.mount("/", StaticFiles(...))` **之前**。
- 首頁 `/` 也一樣：要讓它回傳學生頁。可以直接把學生頁內容放進 `index.html`，或另外寫一個路由。

**未登入時**只顯示「老師登入」區塊：密碼欄與「登入」按鈕，照舊呼叫 `POST /api/auth/teacher-login`。

**登入後**，頁首只保留「登出」按鈕，移除「搶答主控台」「學習單與結果」互相切換的連結。下面由上而下依序顯示：

1. **匯入學習單**：試算表網址、預覽、確認或取消（目前 `index.html` 的匯入區）。
2. **已確認的學習單**：列出已確認的學習單（編號、試算表、題數、題組數、確認時間）。
3. **建立搶答活動**：學習單選單、組名（一行一組）、冷卻設定（目前 `teacher.html` 的建立區）。匯入並確認學習單後，選單要立即更新，不必重新整理頁面。
4. **目前活動（搶答主控台）**（目前 `teacher.html` 的活動區）：
   - 階段、開始搶答、結束搶答。
   - 組別、組別代碼、成功題數、冷卻、重新產生代碼。
   - 作答狀況、判定無效。
   - **活動結束後，在同一區塊顯示「寫回答案」和「下載 CSV」兩個按鈕。** 直接使用這場活動，以及它的 `worksheet_id`，不再需要手動輸入學習單 ID 和活動 ID。
5. **活動清單**：列出所有活動（編號、學習單、階段、建立時間、結束時間），每列有「檢視」按鈕。按下後，該活動顯示在「目前活動」區塊；已結束的活動也能在那裡寫回或下載 CSV。這一區取代目前 `index.html` 的「寫回答案與匯出結果」區（已結束活動選單、學習單 ID、活動 ID 輸入框）。

其他：
- 下載 CSV 後照舊顯示紀錄筆數。沒有紀錄時，顯示「此活動沒有任何送出紀錄」。
- **按「登出」**後回到同一頁的「老師登入」區塊，網址維持 `/teacher`。
- **重新整理頁面時**，sessionStorage 裡有老師 Token，就用 `GET /api/auth/session` 檢查。有效就直接顯示登入後的畫面。
- WebSocket `/ws` 只在老師登入或學生加入之後才建立，登出時關閉。

### 3. 舊網址的處理

- `/student.html` 導回 `/`；`/teacher.html` 導回 `/teacher`。
- 例如在舊檔案裡只留 `<meta http-equiv="refresh" content="0; url=/">`，或在後端回傳 redirect。這樣照舊說明打網址的人，不會進到舊畫面或 404。
- 原本的 `app.js`、`teacher.js`、`student.js` 怎麼合併或拆檔由你們決定。只要學生頁和老師頁各自只載入需要的程式即可。

### 4. 要一起更新的文件

以下檔案提到 `student.html`、`teacher.html`、「搶答主控台」或「學習單與結果」，改完後要同步更新：

- `README.md`：老師與學生的操作說明。
  - 學生開 `http://127.0.0.1:8000/` 輸入代碼。
  - 老師開 `http://127.0.0.1:8000/teacher`，或在首頁按「我是老師」。
- `specs/001-guided-notes-import/spec.md`
- `specs/002-online-buzz-activity/plan.md`、`tasks.md`、`verification.md`
- `src/guided_buzz/web/static/index.html` 裡的提示「學生請開啟 `/student.html`…」，改完後這段不再需要。

如果元件圖或類別圖裡有畫前端頁面，`.puml` 與 PNG 也要一起更新。

## 驗收情境

- **E-01** WHEN 開啟 `http://127.0.0.1:8000/`　THEN 看到「加入組別」表單，以及「加入」「我是老師」兩個按鈕；沒有老師密碼欄。
- **E-02** WHEN 在首頁輸入正確的組別代碼並加入　THEN 同一頁顯示該組的作答畫面，網址仍是 `/`，「加入組別」與「我是老師」都隱藏。
- **E-03** WHEN 在首頁按「我是老師」　THEN 網址變成 `/teacher`，顯示「老師登入」。
- **E-04** WHEN 在 `/teacher` 輸入老師密碼並登入　THEN 同一頁依序顯示匯入學習單、已確認的學習單、建立搶答活動、目前活動、活動清單；網址仍是 `/teacher`；畫面上沒有切換到其他網頁的連結。
- **E-05** WHEN 老師匯入並確認學習單　THEN 不必重新整理頁面，就能在「建立搶答活動」的選單看到它。
- **E-06** WHEN 老師建立活動、開始、讓學生送出、判定無效、結束，再按「寫回答案」與「下載 CSV」　THEN 全程不必離開 `/teacher`，也不必手動輸入活動 ID 或學習單 ID。
- **E-07** WHEN 老師在活動清單按某個已結束活動的「檢視」　THEN 該活動顯示在「目前活動」區塊，可以寫回或下載 CSV。
- **E-08** WHEN 同一個瀏覽器的視窗 1 在 `/teacher` 登入、視窗 2 在 `/` 加入第一組、視窗 3 在 `/` 加入第二組，然後各自重新整理　THEN 三個視窗都維持原本的身分與畫面，互不影響。
- **E-09** WHEN 學生視窗的組別代碼被老師重新產生，或伺服器重啟導致活動已中斷　THEN 該視窗回到首頁的「加入組別」，並顯示原本的提示訊息。
- **E-10** WHEN 開啟 `/student.html` 或 `/teacher.html`　THEN 分別被導回 `/` 和 `/teacher`。

## 不需要改的

- 後端 API、WebSocket 協定、判定、冷卻、權限與資料庫都不變，只新增 `/teacher` 的頁面路由，並調整 `/` 回傳的頁面。
- 現有的自動化測試只要沒有直接測頁面檔名，應該都不受影響。如果要新增前端或路由的測試，請以上面的驗收情境為準。
